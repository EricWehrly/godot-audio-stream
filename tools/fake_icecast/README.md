# fake_icecast

Offline, deterministic Icecast-shaped MP3 server for testing `RadioStream` without a network
dependency or a third party's uptime. See
[`docs/features/fake-icecast-server.md`](../../docs/features/fake-icecast-server.md) for the
design rationale (why a script instead of real Icecast in Docker).

## Quick start

```bash
python tools/fake_icecast/server.py --port 8000
```

Then point `RadioStream` (or `demo/test_stream.gd ++ --url=...`) at
`http://127.0.0.1:8000/stream`.

The fixture (`fixtures/tone.mp3`) is committed — regenerate it only if it needs to change:

```bash
python tools/fake_icecast/generate_fixture.py   # requires ffmpeg on PATH
```

## Fault injection

Every fault is an independent flag; combine as needed:

| Flag | Effect |
|---|---|
| `--drop-after SECONDS` | Closes the connection outright. |
| `--stall-at SECONDS` | Stops sending bytes without closing — a harder failure than a drop. |
| `--truncate` | Cuts the stream mid-MP3-frame near the 32KB mark. |
| `--garbage-at SECONDS` | Corrupts one chunk of bytes once, then resumes clean — tests decoder resync. |
| `--http-error CODE` | Returns that status instead of streaming. |
| `--redirect URL` | Returns a 302 instead of streaming. |
| `--slow-headers` | Trickles response headers one byte per 50ms — exercises the handshake timeout. |
| `--icy-metadata` | Honors `Icy-MetaData: 1` with interleaved `StreamTitle=` blocks. |
| `--bitrate-kbps N` / `--burst-kbps N` / `--burst-seconds N` | Controls steady-state and burst-on-connect rate — reproduces the documented Icecast burst behaviour on demand. |
| `--playlist-format {pls,m3u,m3u8}` + `--playlist-entries URL1,URL2,...` | Serves a playlist body instead of streaming — added for `url-resolution` testing. |

## Verified against real `RadioStream`

Not just a standalone script — spot-checked against the real decoder (2026-09-08):

- **Normal stream, 25s soak:** byte accounting closed exactly
  (`536300 recv = 532317 audio + 0 skipped + 3983 backlog`), 0 starvations, FIFO stable
  ~3s, burst-on-connect handled (1 trim, 0 after settling) — same behaviour the live-station
  soak in the main README showed.
- **`--http-error 404`** → 404 returned.
- **`--redirect`** → 302 with `Location` header.
- **`--drop-after 1`** → connection closes at ~1s, having sent exactly the configured burst
  rate's worth of bytes.
- **`--drop-after 3` against a live `RadioStream`** → `get_status()` reaches `STATUS_ERROR`
  with `"Stream disconnected"`, confirming the fault reproduces the exact documented terminal
  failure `reconnect-resilience` needs to fix.

## Notes

- `ThreadingHTTPServer` is `http.server.ThreadingHTTPServer`, **not**
  `socketserver.ThreadingHTTPServer` — an easy mixup since `BaseHTTPRequestHandler` lives in
  `http.server` but most of its `Threading*` mixin cousins live in `socketserver`.
- The committed fixture leads with an ID3v2.4 tag (ffmpeg adds one by default). Left in
  deliberately — it exercises the decoder's "skip non-audio data at stream start" path for
  free, the same path a real station's ID3-tagged stream start would hit.
- No third-party audio anywhere in this tool or its output (D6) — the fixture is six seconds
  of a hardcoded sine-wave arpeggio, generated by `generate_fixture.py`, content entirely ours.
